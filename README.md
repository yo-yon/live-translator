# 登壇翻訳 LIVE 利用マニュアル

2026-10-27 時点

英語の講演をマイクで拾い、Azure の音声認識と LLM で自然な日本語字幕にするブラウザツールです。使う人ごとに Azure のキーが必要で、ツール本体は URL を開くだけで使えます。

## ほかの人に使ってもらうとき

ツールは URL（https://yo-yon.github.io/live-translator/）を共有するだけで使えます。ツール本体にキーは入っていないので、URL を知られてもキーは漏れません。ただし、使うには Azure のキーが必要で、渡し方は次の2通りです。

| 方法 | 手間 | 費用の支払い | 注意点 |
| --- | --- | --- | --- |
| A. 各自が Azure リソースを作る（推奨） | 1人30分ほど | 使う人のサブスクリプション | この後の「Azure の準備」の手順で作成 |
| B. 自分のキーを渡す | すぐ使える | キーを渡した側（自分）のサブスクリプション | 費用表示は端末ごとなので、合計額は Azure Cost Management でしか分からない |

B で渡す場合は、Teams の個別チャットなど本人だけが見られる場所で渡してください。メールや共有チャンネルには貼らないでください。キーを知っている人は、再生成するまで誰でも使えます。使い終わったら、必ずキーを再生成してください（「使い終わったら」を参照）。

## しくみ

音声は次の順で字幕になります。翻訳が6秒以内に返らないときは機械翻訳に切り替え、それも失敗したら英文をそのまま表示します。

1. マイク（PC 版はシステム音声も可）で登壇者の声を拾う
2. Azure Speech が英語を文字にする（音声認識）
3. 文が確定したら、Foundry の gpt-5.4-mini が自然な日本語に訳す。直前の3文（英文と訳文）とセッション情報を文脈として渡し、聞き取り誤りと思われる語は推測して直す
4. 字幕を表示し、設定によっては読み上げる

必要な Azure リソースは次のとおりです。新しく作る人は、**Foundry リソースを1つ作るだけ**で両方をまかなえます（Foundry リソースには Speech も含まれ、キーを1本で使えるため）。

| 役割 | 使うもの | ツールに入力する値 |
| --- | --- | --- |
| 音声認識 | Foundry リソースの Speech 機能 | Speech キー、Speech リージョン |
| 翻訳（LLM） | 同じリソースにデプロイした gpt-5.4-mini | エンドポイント、Foundry キー、デプロイ名 |

作成者の環境は、Speech 用（East US）と Foundry 用（East US 2）の2リソース構成で動作を確認しています。1リソース構成は Microsoft Learn の説明に基づく手順で、実機では未検証です。

## Azure の準備

Azure サブスクリプションと、リソースを作れる権限（共同作成者または所有者）が必要です。所要時間は30分ほどです。

### ① Foundry リソースを作る

1. Azure portal で [Foundry の作成画面](https://portal.azure.com/#create/Microsoft.CognitiveServicesAIFoundry) を開く
2. 次のように入力する
    - サブスクリプション：使うものを選ぶ
    - リソースグループ：新規作成（例：rg-livetrans）。後でグループごと削除すれば課金が止まります
    - リージョン：**East US 2**（gpt-5.4-mini を Global Standard で使えることを確認済み）
    - 名前：Azure 全体で重複できない名前（例：foundry-livetrans-自分のイニシャル）。エンドポイントの URL になるので、氏名や会社名は避ける
    - プロジェクト名を聞かれたら、任意の名前（例：proj-livetrans）でよい
3. **確認と作成** → **作成** を押し、完了したら **リソースに移動** を押す

### ② 翻訳用のモデルをデプロイする

1. [Foundry ポータル](https://ai.azure.com) を開き、画面上部の「新しい Foundry」をオンにして、①で作ったプロジェクトを選ぶ
2. 右上の **ビルド** → 左の **モデル** → **デプロイ** → **基本モデルをデプロイ** を選ぶ
3. `gpt-5.4-mini` で検索して選び、**デプロイ** → **カスタム設定** を選ぶ
4. デプロイ名を `gpt-5.4-mini`、デプロイの種類を **Global Standard** にして **デプロイ** を押す
5. 一覧で状態が **Succeeded** になれば完了

一覧にモデルが出ないときは、左の「使用可能性」を「すべてのモデル」に切り替えてください。クォータ不足のエラーが出たときは、サブスクリプションの管理者に相談してください。

### ③ キーとエンドポイントを確認する

Foundry ポータルのホーム画面、または Azure portal のリソース画面にある **キーとエンドポイント** で確認できます。ツールには次のように入力します。

| ツールの入力欄 | 入力する値 | 例 |
| --- | --- | --- |
| Speech キー | リソースのキー（「API キー」または「キー1」） | — |
| Speech リージョン | リソースの場所を小文字・空白なしで | eastus2 |
| エンドポイント | 「Azure OpenAI エンドポイント」（プロジェクト エンドポイントではない） | https://リソース名.openai.azure.com/openai/v1 |
| Foundry キー | Speech キーと同じキー | — |
| デプロイ名 | ②で付けた名前 | gpt-5.4-mini |

キーはパスワードと同じ扱いです。チャットやメールに貼らないでください。

## 使い方：PC 版

PC では、URL を開く方法と、ファイルを手元に置いて開く方法のどちらでも使えます。ブラウザは Chrome か Edge を使ってください。

1. https://yo-yon.github.io/live-translator/ を開く（すでにファイルを持っている人は live-translator.html を開いてもよい）
2. 設定画面で翻訳エンジンを **LLM** にし、「Azure の準備」③の5項目を入力する
3. **「この端末にキーと設定を保存」** にチェックして **保存して開始** を押す（次回から入力不要）
4. 音声の入力元を選ぶ
    - **マイク**：会場で登壇者の声を拾う。右のプルダウンでマイクを選べる
    - **システム音声**：YouTube や Teams など PC で再生中の音声を訳す。開始後の画面共有ダイアログで、対象のタブを選んで「タブの音声を共有」をオンにする
5. **▶ 開始** を押し、マイクの使用を許可する
6. 終わったら **■ 停止** を押す

**設定ファイルを使う方法（任意）**：live-translator.html と同じフォルダに live-translator.config.js を置き、キーを書き込んでおくと、開いた時点で設定画面を飛ばせます。キーが平文で入るので、OneDrive などの同期フォルダや GitHub には置かないでください。

## 使い方：iPhone 版

iPhone ではマイク入力だけが使えます。開いた端末に合わせて自動で iPhone 版の画面になり、ヘッダーの「📱 iPhone版／🖥 PC版」ボタンで手動でも切り替えられます。

1. Safari で https://yo-yon.github.io/live-translator/ を開く
2. 設定画面で「Azure の準備」③の5項目を入力し、**「この端末にキーと設定を保存」** にチェックして保存する
3. **▶ 開始** を押し、マイクの使用を許可する
4. セッション中は Safari を前面に出したままにする（画面をロックしたり他のアプリに切り替えたりすると、音声の取り込みが止まる）

- 読み上げは最初はオフです。スピーカーから出すとマイクが拾うので、イヤホンを使うときだけ「翻訳音声」をオンにしてください
- 長いキーは、PC から AirDrop やメモ経由で送って貼り付けると楽です。貼り付けたらメモは削除してください
- iPhone 版は画面表示と字幕の動作をエミュレーターで確認していますが、実機の Safari でのマイク取り込みと読み上げは未検証です

## 画面の見方と主な機能

| 画面の表示・操作 | 意味 |
| --- | --- |
| バッジ「LIVE」「WAIT」「STANDBY」 | 翻訳中／待機中（課金停止）／停止中 |
| 音量バーと白い線 | 入力音量。白い線は待機から再開するしきい値 |
| 診断表示（「✅ Speech 接続OK」など） | 音声入力 → Speech 接続 → 認識 → LLM のどこまで進んだか |
| 薄い英文 | 認識中の発話（まだ翻訳前） |
| 大きな日本語 | 確定した訳文。下の（）内が原文。「・機械翻訳」は LLM の代わりに機械翻訳で訳した印 |
| 右下「翻訳中」 | LLM が訳している発話 |
| 「💴 ¥○ / 累計 ¥○」 | 今回／この端末での累計の概算費用。警告額を超えると黄色。クリックで累計をリセット |
| 🎤 ゲイン | マイク入力の増幅（1.0〜5.0倍）。動かすとすぐ反映。数字がオレンジ色になったら音割れしているので下げる |
| 🗣 速度 | 読み上げ速度（0.7〜2.0倍）。次の文から反映 |
| 「📸 スクショ」（PC）「📷 撮影」（iPhone） | 画面や会場のスクリーンを撮影し、字幕ログに追加（「写真・スクショの撮影」を参照） |
| 字幕ログの「レポート出力」 | 字幕と写真を時系列に並べた HTML を1ファイルで保存（写真も埋め込み） |
| 字幕ログの「CSV出力」 | 原文・訳文・時刻・翻訳方式を CSV で保存。写真は「[写真]」の行として入る |
| 字幕ログの「クリア」 | 字幕ログと写真を消去（消す前に確認が出る） |
| 「📝 メモ」 | 押した時刻の位置に所感を書き込む（「メモ（セッションの所感）」を参照） |

字幕ログと写真はブラウザの中にも保存され、タブを閉じても開き直せば復元されます。消えるのは「クリア」を押したときだけです。

**待機と自動再開**：無音が3分続くと、Speech との接続を切って課金を止めます（WAIT）。声を検出すると、直前2秒分の音声ごと自動で再開します。待機が30分続くと完全に停止します。会場の雑音で勝手に再開するときは、設定の「声で自動再開の感度」を「低」にします。

**セッション情報**：設定の「🎤 聴講中のセッション」に、セッション名と概要（アプリやスケジュールの説明文）をそのまま貼り付けます。話題が分かると、聞き取り誤りを AI が正しく推測しやすくなります。セッションが変わったら貼り替えてください。端末に記憶されます。

**途中で切れた発話**：「and」「the」などで終わる発話や4語以下の短い発話は、すぐには訳さず、次の発話とつなげてから訳します。その間、英文は薄く表示されます。次の発話が5秒来なければ、そのまま訳します。字幕が遅れるのが気になるときは、設定の「途中で切れた短い発話」を「そのまま単独で訳す」にします。それでも意味をなさない断片は「…」として字幕ログにだけ残し、画面の字幕は切り替えず、読み上げもしません。

**通信が切れたとき**：一度つながった後に通信が切れた場合は、2秒後に自動で再接続します（最大3回）。

## 写真・スクショの撮影

撮った写真は、撮った時刻の位置で字幕ログに入ります。後で「レポート出力」を押すと、字幕と写真を時系列に並べた HTML として保存できます。

| 端末 | ボタン | 撮れるもの | 使えるとき |
| --- | --- | --- | --- |
| PC | 📸 スクショ | 画面共有しているタブの画面（スライドなど） | 「システム音声」で画面共有している間だけ。マイク使用時はボタンが出ない |
| iPhone | 📷 撮影 | 背面カメラで会場のスクリーン | いつでも |

**PC で撮る**

1. 音声ソースを「システム音声」にして開始し、画面共有を始める
2. 残したい場面で **📸 スクショ** を押す（画面が一瞬白く光れば撮影完了）

**iPhone で撮る**

1. **📷 撮影** を押すと、ツールの画面の中でカメラが開く（初回はカメラと「動作と方向」へのアクセスを許可する）
2. 必要ならズームする。**2本指で広げるとズームイン、つまむとズームアウト**。「1x」「2x」「3x」ボタンでも切り替えられる
3. 会場のスクリーンに向けて赤いシャッターを押す。続けて何枚でも撮れる
4. **閉じる** で翻訳画面に戻る

**ズーム**：iPhone のカメラがズームに対応していればカメラ本来の最大倍率まで、対応していなければ中央を切り出すデジタルズームで最大4倍まで寄れます。今の倍率は画面上部に表示され、デジタルズームのときは「（デジタル）」と出ます。

**写真の向き**：「向き：自動」のときは、縦向きロックのまま横に構えて撮っても、傾きセンサーで判定して横向きの写真として保存します（画面上部に「横向きで保存」と出ます）。ボタンを押すたびに「自動 → 横（右回転）→ 横（左回転）→ そのまま」と切り替わり、選んだ向きは次回も引き継がれます。

- iPhone の標準カメラアプリに切り替えると、Safari が裏に回ってマイクが止まります。必ずツールの「📷 撮影」で撮ってください
- カメラを閉じたときに「⚠ マイクが止まりました」と出たら、**■ 停止 → ▶ 開始** で再開してください
- 写真は長辺1600ピクセルに縮小し、1枚あたり約150〜300KB で保存されます
- 字幕ログのサムネイルを押すと大きく表示されます。向きが違っていたら **↻ 90°回転** で直せます（直した結果は保存されます）

## メモ（セッションの所感）

「📝 メモ」で、気づきや所感を字幕ログに書き込めます。PC と iPhone のどちらでも使え、翻訳は止まりません。

1. 気になった場面で **📝 メモ** を押す
2. 所感を入力して **保存** を押す（改行も使える）

- メモは **ボタンを押した時刻の位置** に入ります。書いている間に字幕が進んでも、メモはその前に入ります
- 字幕ログでは黄色い枠で表示されます。タップすると編集・削除できます
- 「レポート出力」では先頭に **メモ一覧** が並び、時刻を押すと本文のその位置に移動します。CSV には「メモ」の行として入ります
- 字幕や写真と同じくブラウザに保存され、タブを閉じても残ります
- iPhone では、キーボードの音声入力（マイクのボタン）を使うと翻訳用のマイクが取られる可能性があるので、手で入力してください

## 費用の目安と節約のしかた

翻訳している間の費用は **1時間あたり約200円** です（1ドル＝160円での概算）。内訳の大半は音声認識の時間課金で、LLM の翻訳は1文あたり約0.2円です。

| 使い方 | 概算 |
| --- | --- |
| 講演1本（60分） | 約200円 |
| 1日に5セッション | 約1,000円 |
| 終日ワークショップ（実翻訳4〜6時間） | 約800〜1,200円 |

- 使わないときは停止するのが一番効きます。音声認識は、接続している間は無音でも課金されます（待機中は課金されません）
- 画面の金額は単価と為替から計算した概算です。実際の請求額は Azure Cost Management で確認してください（反映まで1日ほどかかることがあります）
- Azure の予算アラートは通知だけで利用は止まらないので、画面の警告額もあわせて設定しておくと安心です
- 音声認識（$1/時）と gpt-5.4-mini の単価は非公式の比較サイトの値です。正確な単価は Azure の料金ページで確認してください

## 困ったとき

まず、ステータスの右に出る診断表示を見てください。どこで止まっているかで原因が分かります。

| 症状 | 主な原因 | 対処 |
| --- | --- | --- |
| 「❌ 認識エラー(4)：Unable to contact server… 1006」 | Speech キーとリージョンの組み合わせ違い | リージョンをキーのリソースの場所に合わせる（例：East US 2 なら eastus2） |
| 音量バーが動かない（🔇 音声入力なし） | マイクの許可がない／別のマイクを使っている／共有したタブで音が出ていない | ブラウザのマイク許可、マイクの選択、「タブの音声を共有」を確認 |
| 英文は出るが訳が出ない（❌ LLM 失敗） | エンドポイント・キー・デプロイ名の誤り | エンドポイントは「Azure OpenAI エンドポイント」か、デプロイ名が一致しているか確認 |
| 訳に「・機械翻訳」が付く | LLM が6秒以内に返らなかった（回線が遅いなど） | そのまま使える。続くようなら回線を切り替える |
| 英文が途切れる・認識されない語が多い（音量バーが短い） | 登壇者の声が小さい／スピーカーから遠い | 「🎤 ゲイン」を2〜3倍に上げる。オレンジ色になる手前まで。上げると雑音でも待機から再開しやすくなるので、その場合は再開の感度を「低」に |
| 読み上げがときどき飛ぶ | 読み上げが登壇者に追いついていない | 「🗣 速度」を1.3〜1.5倍に上げる |
| 訳に話題と関係ない語が出る（「アルコール」など） | 英語の聞き取り誤り | 設定の「🎤 聴講中のセッション」にセッション名と概要を貼る。よく出る固有の語は用語集に追加する |
| 待機から勝手に再開する | 会場の雑音や拍手 | 設定の「声で自動再開の感度」を「低」にする |
| 開いても「Speech SDK 読み込み失敗」 | インターネットにつながっていない | 接続を確認して再読み込み |
| 「📸 スクショ」が押せない（PC） | 画面共有していない／翻訳を開始していない | 「システム音声」で開始し、画面共有している間に押す |
| カメラを閉じたら「⚠ マイクが止まりました」（iPhone） | カメラの起動で iPhone がマイクを止めた | ■ 停止 → ▶ 開始 で再開する |
| カメラが開かない（iPhone） | Safari にカメラの使用を許可していない | 設定 → Safari → カメラ で許可する |
| 写真が横倒しになる（iPhone） | 傾きセンサーが使えない／「動作と方向」を許可していない | カメラ画面の「向き」を手動で指定する。撮った後はサムネイルの「↻ 90°回転」で直せる |
| メモを書いたら翻訳が止まった（iPhone） | キーボードの音声入力がマイクを使った | ■ 停止 → ▶ 開始 で再開し、メモは手入力にする |

## 対話版（conversation.html）

対面で2人が交互に話し、互いの発話を相手の言語に訳して読み上げる版です。URL は https://yo-yon.github.io/live-translator/conversation.html です。

- **キーはライブ版と共通**：ライブ版で「この端末にキーと設定を保存」していれば、対話版でもそのまま使えます。設定ファイル（live-translator.config.js）も共用です
- **使い方**：話す人が自分の側のボタンを押して話し、話し終わったらもう一度押します。訳が相手側に表示され、相手の言語で読み上げます。読み上げ中にボタンを押すと読み上げが止まります
- **iPhone 版**：画面は上下2分割で、上が相手側（話者A）、下が自分側（話者B）です。ヘッダーの「↕」を押すと上側が180度回転し、テーブルの向かいの相手が読めるようになります
- **多言語モード**：最大4言語から話者の言語を自動で判定し、ほかの参加言語すべてに訳します
- **翻訳エンジン**：既定は LLM（gpt-5.4-mini）です。不調なときは設定画面で「Speech 翻訳（従来方式）」に切り替えられます
- **費用**：録音している間だけ課金されます。画面上部に概算（対話版だけの累計）を表示します

## 使い終わったら

キーをだれかに渡した場合や、ファイルや端末に保存した場合は、使い終わったらキーを無効にしてください。

1. **字幕ログと写真を保存してから消す**：「レポート出力」で保存してから「クリア」を押す。消さないと、ブラウザの中に残り続けます
2. **キーを再生成する**：Azure portal でリソースを開き、**キーとエンドポイント** で **キー1を再生成**、**キー2を再生成** を押す。古いキーはすぐ使えなくなります
3. **端末に保存したキーを消す**：ツールの設定画面で「この端末にキーと設定を保存」のチェックを外して保存する。設定ファイル（live-translator.config.js）を使っていれば削除する
4. **もう使わないならリソースを削除する**：Azure portal の **リソースグループ** で対象のグループを開き、**リソースグループの削除** を押す。グループ内のリソースはすべて削除されます

このツールは、使っていないときは課金されません。リソースを残しておいても、翻訳しなければ費用はかかりません。
