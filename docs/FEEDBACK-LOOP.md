# 改善ループ — 仕組み

```
利用者のサーバー版 ─👎・ご意見・字幕ログ─▶ 自分のストレージ（常に）
        │ FEEDBACK_HUB_URL を設定した環境で、利用者が選んだものだけ、サーバー間で転送
        │   👎・ご意見：1件ごとに「作者にも送る」を選んだもの（初期設定は送らない）
        │   字幕ログ：設定画面でオンにした人の分（初期設定はオフ）
        │ メール・URL・電話番号は伏せる。名前・アカウントは送らない
        ▼
作者の受付 feedback-hub（English Trainer と共通。作者の Azure・非公開リポジトリ）
        │ ① 毎週日曜 21:23（日本時間）GitHub Actions「Weekly hub report」が集計 → reports ブランチ
        ▼
② 毎週月曜 早朝：Claude の定期タスクが集計を読み、このリポジトリに改善案のプルリクエストを作る
   - terms.json：用語（products）・聞き取りのヒント（hints）・聞き間違いの例（asrFixes）
   - index.html：翻訳指示（buildSystemPrompt）や小さな不具合
        │
        ▼
③ 作者がプルリクエストを確認して取り込む
   → GitHub Pages 版は自動で更新、サーバー版の利用者は「Sync fork」で更新
   → 対応したフィードバックは、次の定期タスクが feedback-hub の「Close feedback」で「対応済み」にする
     （プルリクエスト本文の `Fixes-hub: <ID>` を使う。手動なら feedback-hub の管理画面でも可）
```

## ファイルの役割

| ファイル | 中身 | 改善ループで更新するか |
|---|---|---|
| `terms.json` | 英語のまま残す製品名、音声認識のヒント、聞き間違いの例 | ✅ 主にここ |
| `index.html` | 画面とロジック。`terms.json` が読めないとき（ファイルを直接開いたとき）用の組み込みの用語も持つ | 翻訳指示・不具合のみ |
| `api/` | サーバー版の API（キーはここだけが持つ） | 不具合のみ |

## 守ること

- AI に任せるのは**提案まで**。取り込みは人が判断する（推測の誤りが全員に配られるのを防ぐ）
- 公開リポジトリなので、プルリクエストの本文に利用者の字幕やコメントをそのまま書かない（要約と件数だけ）
- 用語の追加は、公式の製品名か確かめてから。確かめられないものは「判断が必要」に回す
